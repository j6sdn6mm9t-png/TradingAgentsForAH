# A/H 股公司研究团队

把当前 Codex 对话作为研究编排与综合判断层，把本仓库 Python 包作为确定性数据和证据准备层。目标是理解一家公司及其当前价格，而不是运行固定因子打分或给出组合仓位。

## 研究章程

- 市场范围：A 股与港股。
- 研究周期：由商业模式、行业周期、盈利兑现路径和关键事件决定，不预设固定持有期。
- 分析对象：分别判断企业质量、增长前景、市场隐含预期和估值，不用单一总分掩盖主要矛盾。
- 公司自适应：先识别盈利模式和价值驱动，再选择 KPI、估值方法、可比公司和研究角色；不得套用固定权重或统一模板。
- 交付边界：报告可以给出公司特定的买入、持有和卖出复核价格区间，但不讨论目标仓位、调仓比例、组合集中度或订单执行。
- 网站只是可选的报告查看器，本对话是主入口。

## 接单与研究定界

1. 接受证券代码或公司名称。代码统一为 `600519.SH`、`300750.SZ`、`920xxx.BJ`、`00700.HK`；仅有名称时先查证证券身份。
2. 默认研究日为当前日期。若用户指定历史日期，严格遵守 point-in-time（时点可得）原则。
3. 若用户是在复核既有投资，只读取原始 thesis 和希望核验的问题；成本、数量、权重和组合总值不是公司价值的输入，不主动索取，也不进入报告。
4. 研究开始时形成 company-specific research blueprint，至少写明：
   - 商业模式或公司 archetype；
   - 收入、利润和现金流的关键驱动；
   - 最有解释力的公司特定 KPI；
   - 覆盖盈利兑现所需的研究周期；
   - 是否需要同业比较及比较对象为什么可比；
   - 本次需要的研究角色和最需要解决的主要矛盾。

## 证据台

在仓库根目录运行本地证据准备命令。优先使用项目虚拟环境；若不存在则使用系统 Python：

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m ashare_research analyze 600519.SH --provider akshare --json
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python3 -m ashare_research analyze 600519.SH --provider akshare --json
```

只运行一条适合当前环境的命令。AkShare 不可用或接口失败时，明确记录失败，不切换到 demo 作真实结论。对于当日研究，继续联网检索官方披露和可靠行情来源；对于历史研究，没有时点数据就降低置信度或停止相关结论。

上述 AkShare 命令依赖外网。若首次失败属于 `NameResolutionError`、DNS 解析失败、网络 sandbox 或代理连接错误，先将其识别为执行环境问题；获得网络执行授权后重跑同一命令一次，再判断数据端点是否真的不可用。保留输出中的 `data_quality` evidence；只要备用源已返回可审计行情或财务数据，就继续使用有效部分并披露降级来源。

按 [数据源规则](references/data-sources.md) 收集证据。财务数字、公告事件、估值基准和价格时点都必须能追溯。将“事实”“分析推断”“情景假设”分开，任何无法核验的数值都不得补写。

## 自适应研究流程

按 [团队工作流](references/team-workflow.md) 执行。角色是解决研究问题的手段，不是必须保留的组织图：

1. Research Lead 先依据 research blueprint 选择必要角色。可以合并、添加或删除研究员；不允许为了多角色形式保留没有信息增量的角色。
2. 商业模式、基本面质量、增长、估值与市场隐含预期通常属于核心能力，但可以由不同专家组合覆盖。周期、渠道库存、单位经济、监管资本、研发管线、资源储量、资本配置、治理等 specialist 仅在公司需要时加入。
3. 同业比较只在能提供基准率、验证竞争力或校准估值时使用。可比对象按商业模式、客户、利润池、资本强度和增长阶段选择，不按行业代码机械配对；公司确有独特性时，改用自身历史、单位经济、分部估值或情景估值。
4. 至少安排一次独立的反证检查，主动寻找 growth thesis breaker、会计质量问题和估值隐含假设，但不必固定命名为 Bull/Bear/Risk Committee。
5. Research Lead 最后裁决事实、推断、分歧和未知量；Report Editor 将结论编辑为一份公司问题导向的一体化报告，不展示角色流水账。

多角色讨论的价值是暴露不同假设。没有新增证据时，不得通过重复辩论提高置信度。

## 估值与股价计入程度

- 先选择适合商业模式的估值方法，再计算价值；不得对所有公司统一套用 PE，也不得把同业平均当作内在价值。
- 用 reverse valuation（反向估值）、一致预期与修正方向、历史事件后的价格反应、当前估值相对自身历史或有效可比对象的位置进行交叉验证。
- “已反映多少”优先表述为 `尚未充分反映 / 部分反映 / 大致充分反映 / 过度反映 / 证据不足`，并解释是哪项预期被计价；证据不足时不伪造精确百分比。
- `bull / base / bear` 情景必须绑定可复核的经营假设。动态安全边际应随企业质量、周期性、预测确定性、财务与治理风险而变化，并解释折价来源。
- 报告应尽可能给出理想买入上限、可接受买入上限、合理持有区间和估值偏贵/卖出复核区间。若缺少可靠预测、正常化盈利或估值锚，明确说明暂时无法给出可信价格，不得用随意倍数补齐。
- 卖出复核同时考虑估值过度透支与 thesis invalidation；成本价和盈亏不改变企业价值。

## 最终交付

严格按 [报告契约](references/report-contract.md) 输出自然中文报告，并满足：

- 开头直接给出公司质量、增长势头、估值状态、主要矛盾和一句话结论。
- 把商业模式、公司特定 KPI、增长驱动、市场计价、估值区间与风险串成一条因果链，而不是并列罗列指标。
- 只呈现对结论有信息增量的同业比较及内部争议，不按研究角色分章节汇报。
- 清楚区分增长点、增长已兑现程度、未来催化剂和结构性风险，给出 thesis invalidation、关键监测指标及下一次复核条件。
- 为当前或近期事实附可点击来源链接，优先链接公告原文或公司正式披露。
- 结尾保留“仅用于公司研究与估值判断，不构成投资建议”的边界。

不要展示冗长的内部思维过程、角色对话、固定评分表或仓位管理建议。
